Xiaomi Mi Router AX3000T v2 (RD03v2) OpenWrt port — overlay manifest
=====================================================================
Base:   openwrt/openwrt @ 25ee12629edcc38feffbd06255dd47840cd7af7e
        ("uboot-tools: update to v2026.07")
Device: IPQ5018 SoC (2.4 GHz radio) + QCN6122 (5 GHz) + Airoha AN8855 4-port switch
Usage:  ./build.sh  (clones OpenWrt, checks out 25ee126, overlays files/, builds)

Every path below is relative to files/ and lands at the same path inside
the OpenWrt tree. Sizes in bytes. [bin] = binary, keep byte-identical.

Deliberately excluded: target/linux/qualcommax/ipq60xx/config-default and
ipq807x/config-default diffs from the source tree — they only add
"# CONFIG_*AN8855* is not set" housekeeping for those sibling subtargets
(new Kconfig symbols introduced by our kernel patches default to n anyway).
Not needed for an ipq50xx-only build.

  2162  package/kernel/mac80211/patches/ath11k/950-wifi-ath11k-implement-CE-interrupt-enable-disable-for-AHB.patch
         Issue #15. ath11k_ahb_hif_ops_ipq8074 never set ce_irq_enable/
         ce_irq_disable, so ath11k_hif_ce_irq_disable() was a no-op on AHB
         and the copy-engine tasklets stayed live across rproc_shutdown().
         From openwrt/openwrt#24578.
  2786  package/kernel/mac80211/patches/ath11k/953-wifi-ath11k-disable-interrupts-during-firmware-crash-recovery.patch
         Issue #15. Without it a firmware assert panics on a freed datapath
         (null deref in ath11k_hal_srng_access_begin from the monitor rings)
         and the SoC reboots. From openwrt/openwrt#24578, renumbered off
         951 which is taken here.
  2391  package/kernel/mac80211/patches/ath11k/954-wifi-ath11k-only-spare-the-wake-CE-on-chips-that-can-suspend.patch
         Issue #15. The except_wake_irq pair skips CE2 so a chip suspended
         with WoW keeps its wakeup interrupt armed - but the recovery path
         re-enables every CE, so on chips that cannot suspend at all
         (qcn6122, wcn6750) each crash recovery did one surplus
         enable_irq(): "Unbalanced enable for IRQ 67", 22 times across a
         24-cycle soak. Skip the wake CE only when
         hw_params.supports_suspend. Verified: 6 crash cycles after, zero
         warnings.
   1791  package/kernel/mac80211/patches/ath11k/951-wifi-ath11k-introduct-CONFIG_ATH11K_SMALLBUFFERS.patch
         Ziyang Huang's patch (OpenWrt PR #21495, authorship preserved):
         gates ath11k's DP ring-buffer sizes behind CONFIG_ATH11K_SMALLBUFFERS
         so they shrink on low-RAM devices. Halves the ath11k footprint.
  12707  package/kernel/mac80211/Makefile
         Adds -DCONFIG_ATH11K_SMALLBUFFERS to the smallbuffers build variant
         (mirrors the existing ath10k-smallbuffers define).
  15461  package/kernel/mac80211/ath.mk
         Splits kmod-ath11k into regular + smallbuffers variants
         (kmod-ath11k-smallbuffers, PROVIDES kmod-ath11k). Our device
         selects the smallbuffers variant in ipq50xx.mk DEVICE_PACKAGES.
  12752  package/kernel/mac80211/patches/ath11k/952-wifi-ath11k-fix-rx-signal-reporting-on-IPQ5018-QCN6122.patch
         Issue #3. The WLAN.HK.2.7 firmware reports rx signal on an
         uncalibrated dB scale (~31 dB low on 2.4, ~24 on 5) and an
         impossible noise floor. Applies per-chip offsets at every dB->dBm
         site and implements the firmware's dormant GET_NFCAL_POWER exchange
         for a real per-channel noise floor. Host-side: no board file fixes it.

 10266  target/linux/qualcommax/ipq50xx/base-files/usr/sbin/rd03v2-watchdog
         Issue #15. Backstop for the WiFi failures the driver does not
         recover by itself: any of remoteproc0/pd-1/pd-2 not "running"
         for 2 samples, or the in-use channel's survey active time frozen
         for 4 (the silent death, which raises no fatal IRQ). Escalates
         rather than rebooting first - ath11k reset of the affected radio
         (~1s), then that user PD stopped and started (~16s), and only
         then a reboot. Evidence is written before anything is touched.
         At most 3 in-place attempts per hour, 10-minute minimum uptime
         and a 1-hour hold between reboots. Touch
         /etc/rd03v2-watchdog.disable to neuter it. See
         docs/q6-firmware-crash.md.

  1811  target/linux/qualcommax/patches-6.12/0819-remoteproc-qcom_q6v5_mpd-fix-userpd-array-overflow.patch
         Issue #15. qcom_get_pd_asid() returns 1..3, but struct q6_wcss's
         upd[] has only MAX_UPD (3) entries, so registering pd-3 writes one
         pointer past the end. Harmless only because upd[] is the last
         member; it corrupts whatever is added after it.
  2507  target/linux/qualcommax/patches-6.12/0821-remoteproc-qcom_q6v5_mpd-tear-down-user-pd-when-root-pd-is-dead.patch
         Issue #15. On a ROOT pd fatal the user PDs still read RPROC_RUNNING,
         so wcss_pd_stop() waited for a stop-ack from dead firmware, timed
         out, and returned before the MSA unlock and the rproc_shutdown()
         that drops the root's refcount. Skip the handshake when the root
         is CRASHED/OFFLINE. Measured: the stop went from -ETIMEDOUT after
         5 s (state stuck "running") to rc=0 reaching "offline".
   3820  target/linux/qualcommax/patches-6.12/0413-mtd-spinand-winbond-add-W25N01KW-support.patch
         Issue #12. The SPI-NAND is second-sourced: some units carry a Winbond
         W25N01KW where others have the ESMT F50D1G41LB, and the Winbond part
         was missing from the kernel ID table, so the probe aborted and no MTD
         device was registered at all. Mirrors the 64-byte-spare W25N01GW
         geometry, NOT the 96-byte W25N01KV - the KV OOB layout would address
         spare this chip does not have. ESMT units cannot reach this entry
         (different manufacturer table and read-ID method).
  2039  target/linux/qualcommax/patches-6.12/0822-remoteproc-qcom_q6v5_mpd-unwind-a-failed-root-pd-start.patch
         Issue #15. q6_wcss_start() returned on failure without
         qcom_scm_pas_shutdown() or qcom_q6v5_unprepare(), so every retry
         inherited the previous failure (and leaked an IRQ enable, the
         "Unbalanced enable for IRQ" warning). Also takes the start
         timeout from 5 s to the vendor's 10 s.
  4043  target/linux/qualcommax/patches-6.12/0918-soc-qcom-smp2p-clear-cached-inbound-values-on-restart.patch
         Issue #1, the actual fix for a dead radio. smp2p only raises an
         interrupt for bits that CHANGED, but its SMEM items outlive the
         Q6: on restart the firmware republishes the same ready bit, the
         XOR is zero, and wait_for_start() times out on a processor that
         booted fine. Clears the cached values while the Q6 is held in
         reset. Pairs with qcom,smp2p-feature-ssr-ack in the board DTS -
         both are required.
  12419  target/linux/qualcommax/patches-6.12/737-net-dsa-add-Airoha-AN8855.patch

NSS hardware-offload overlay (nss/) — applied only with `NSS=1 ./build.sh`
=====================================================================
Experimental; see docs/nss-offload.md. Layered on top of files/:

        nss/feeds.conf.append   Extra feeds: qosmio nss-packages + sqm-scripts-nss.
        nss/config.append       NSS kernel symbols (skb_recycler, conntrack DSCP-remark,
                                and NET_DSA_TAG_VSC73XX_8021Q for the offload DSA tagger).
        nss/feed-patches/qca-nss-drv/0029-ipq50xx-nss-core-boot-reset-pulse.patch
                                The IPQ5018 NSS core-boot fix (reset-pulse), applied to
                                the qca-nss-drv feed package after `feeds update`.
        nss/feed-patches/qca-nss-ecm/0026-frontends-nss-dsa-conduit-awareness.patch
                                ECM DSA front-end: maps a DSA user port (or a bridge
                                master over one) to its CPU conduit so the fast path
                                resolves an accelerable NSS interface.
        nss/overlay/            Path-preserving overlay (same layout as files/). It is
                                PURELY ADDITIVE: no file here shadows one in files/.
                                files/ is the single source for anything both builds
                                share - see "The two builds" below.
          patches-6.12/06xx,0819,0981  ECM/clients/skb_recycler + NSS reserved-memory.
          patches-6.12/999-2758  tag_8021q core: the NSS driver expressed as a delta on
                                 999-2757 (was a full forked copy of an8855.c until v1.6).
          patches-6.12/999-2759  tag_8021q bridge-leave (issue #1/#2).
          patches-6.12/999-2760  tag_8021q host-FDB VID (issue #7).
          patches-6.12/999-2761  user-port flood default (issue #5).
          patches-6.12/999-2762  bridge VLAN filtering / shadow PVIDs (issue #11).
          files/.../ipq5018-nss.dtsi   NSS core node (CSM regs, 8 IRQs, 8 MB DDR @0x40000000).
          files/net,include/           skb_recycler + conntrack DSCP-remark sources.
          ipq50xx/.../etc/uci-defaults/00-nss-manual  Disables the qca-nss init scripts so
                                       they don't double-load the autoloaded modules.
          etc/modules.d/33-qca-nss-ecm ECM autoload at boot (pulls in qca-nss-drv, boots core).
        build.sh (NSS=1) additionally, as in-place edits rather than file copies:
          - appends the NSS packages to the AX3000T DEVICE_PACKAGES
          - #includes ipq5018-nss.dtsi into the device DTS
          - appends nss/config.append to target/linux/qualcommax/config-6.12
          - appends nss/feeds.conf.append to feeds.conf.default
          - adds the WAN->eth0 conduit line to board.d/02_network
          - prepends the /proc/sys/dev/nss knobs to etc/rc.local
          - strips +kmod-bonding from qca-nss-clients, copies the feed patches,
            and pins CONFIG_NSS_FIRMWARE_VERSION_12_5

        build.sh (KMODS=1) appends CONFIG_ALL_KMODS=y and builds with
        IGNORE_ERRORS="n m" BUILD_LOG=1. Every kmod is then compiled and
        packaged as `m` - packaged, never installed, so the image's package
        set is unchanged. It is NOT image-neutral though: package-metadata.pl
        collects Kernel-Config symbols from any package that is not 'n', and
        .vermagic is an md5 over the sorted '=[ym]' set, so the kernel package
        version changes. Kmods therefore only install on an image from the
        same build run, which is why release images are built with KMODS=1.
        tools/mkrelease.sh pairs each image set with its own tree's kmods and
        refuses to mix them.

        The two builds
        --------------
        files/ is the ONLY copy of drivers/net/dsa/an8855.c. The default build is
        that file + 999-2757; the NSS build is the same file + 999-2757 + the five
        999-27xx patches above. A fix to the shared driver therefore reaches both
        builds automatically, and a change that collides with the NSS delta fails
        the build loudly instead of silently shipping a stale second copy.

        Until v1.6 nss/overlay/ shipped a complete second an8855.c that replaced
        the files/ one at build time. Fixes to either copy never reached the other:
        that is what caused issue #9 and three further one-sided bugs. Do not
        reintroduce a shadowing copy - tools/check-nss-divergence.sh fails if one
        appears, and build.sh runs it on every build.
