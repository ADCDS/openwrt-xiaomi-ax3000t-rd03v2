--- Two notes ---

1. ipv4_create_requests stays 0 here and that is CORRECT: this node is a dumb
   AP. It bridges, it does not route, so ECM has no NAT flow to accelerate. The
   offload's value on this box is the Wi-Fi datapath itself, not connection
   acceleration. The counter test belongs on the gateway.

2. Clients came back slowly - 1 of 4 after eight minutes. Roaming is
   client-driven (the node README says so), and the gateway carries the same
   <redacted-ssid> SSID, so stations that moved there during the ~3 minute outage stay
   until they have a reason to move back. Not a fault; worth knowing before
   anyone reads the count as a regression.

--- A build bug this flash exposed ---

The first AP build FAILED at target/linux install:

    openwrt-qualcommax-ipq50xx-/home/agiu/.../nodes/ap-rd03v2.manifest:
        No such file or directory

PROFILE is an OpenWrt build variable (include/target.mk:143,
include/image.mk:137 -> PROFILE_SANITIZED -> the manifest filename). Exporting
our profile path let make inherit it. build.sh now unsets PROFILE after copying
files/ (commit 7698ffe).

Worth keeping: the failure lands AFTER all four images are written, and the
shipped squashfs was actually correct. Only the manifest step died. Reading the
artifact list would have called this build good; reading the exit status is what
caught it.
