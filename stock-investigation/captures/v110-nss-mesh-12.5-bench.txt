NSS 802.11s mesh offload on NSS firmware 12.5 - bench run, 2026-09-26 (issue #21, "fix 1")
==========================================================================================
Bench unit only (192.168.1.1, reached over hal's USB-eth on lan2). Branch nss-mesh
(worktree mesh-nss/), flag WIFI_NSS_MESH=1.

PHASE 0 - capability handshake on the installed v1.10 12.5 image (probe kmod, no flash)
  NSS_WIFILI_SEND_MESH_CAPABILITY_INFO, sent the way donor ath11k_nss_mesh_capability() sends it:
    if 203 (NSS_WIFILI_INTERNAL_INTERFACE, radio0): response ACK (0) error 0
    if 215 (NSS_WIFILI_EXTERNAL_INTERFACE0, radio1): response ACK (0) error 0
  cap_info.mesh_enable in the reply echoes the request (sent 0 -> 0, sent 1 -> 1), so it
  carries no signal. Only the response code counts, and ath11k enables mesh offload on != EMSG.

ROOT CAUSE FOUND, 27 Sep
  Test 1, native-wifi AP (frame_mode=1): radio1 AND radio0 both fail the WPA 4-way handshake (reason 15),
    with no data frame reaching the host. frame_mode=1 AP mode is broken on both socs in this stack. It
    does not discriminate between radios; not pursued further.
  Confound found: every radio1 test used an OPEN mesh (the gateway's iw-only mesh), while the working
    radio0 tests used SAE (syd). Code: ath11k authorizes a peer in NSS (NSS_WIFILI_PEER_UPDATE_AUTH_FLAG)
    only in ath11k_mac_op_set_key(), and ASSOC->AUTHORIZED sends nothing to NSS for AP or mesh peers.
    A keyless peer is never authorized in NSS.
  Test A, radio0 with an OPEN mesh to syd (no gateway): 0/20, no frame reaches the host, exactly like radio1.
  Fix 999-991 (authorize mesh peers in NSS at AUTHORIZED) plus TEMP A/B switch and NSS per-peer stats
    (nss_peer_stats_config=1):
      fix on:  "keyless mesh peer 14:cc:.. authorize sent"; NSS peer recvd=21 ucast=21 unauth_drop=0;
               host mesh_obj_data +21. After path warm-up syd->bench 20/20 and bench->syd 20/20.
      fix off: "authorize SKIPPED"; 0/20; NSS peer recvd=0 unauth_drop=23.  MECHANISM PROVEN.
  GATEWAY WINDOW 4 (01:24:38-01:28:17Z, radio1/QCN6122, open mesh, fix on): "keyless mesh peer
    02:99:7f:3a:2c:01 id 8 authorize sent" on soc 215. Gateway->bench 20/20 with normal ARP; 1400-byte
    20/20 at 3.2 ms avg; NSS mesh decap rx_packets and rx_fwd_success +43; NSS peer recvd=32 unauth_drop=0.
    => 5 GHz NSS mesh offload WORKS on the QCN6122. The window-1..3 "firmware drop" was this auth bug.
    (bench->gateway pings fail by design: the gateway's fw4 rejects input on the unzoned test netdev.)
    Peer router unchanged before and after.
  Second bug, recovery: after a hw-restart the peer is re-authorized and RX works, but TX to the peer dies.
    The NSS mesh object comes back with an EMPTY path table, mac80211 sends only UPDATEs, and NSS answers
    "not found" (wifi_mesh_not_found; "failed to update mpath entry"). Reproduced on radio0 with syd:
    0/10 three times after the restart. Fix candidate 999-992 (mac80211: flush mesh paths on reconfig
    when the hw offloads them) is being built.
  Latent: ath11k is compiled without -DNSS_FIRMWARE_VERSION_12_5 while qca-nss-drv (and ECM) use it.
    struct nss_wifili_rx_ctrl_stats has 12.5-only fields, so ath11k parses NSS peer-stats syncs with the
    wrong layout. They are only used when nss_peer_stats_config=1, which is off by default.
